# mindmap-html-generator-design-upgrade - Work Plan

## TL;DR (For humans)
**What you'll get:** The generated mind-map HTML will get a real design system before visual edits begin, then a classroom-ready template pass: clearer hierarchy, calmer whiteboard-style surfaces, better Korean readability, stronger mobile/print behavior, and verified interaction states.

**Why this approach:** The current template already works, but its visual choices live only as scattered CSS. A `DESIGN.md`-first pass makes the design reusable and keeps the Miro/IBM/Apple/Cursor/Airbnb references as inspiration without cloning any brand.

**What it will NOT do:** It will not implement a framework app, marketing page, brand clone, retro/campaign/developer aesthetic, or default quizzes/games/animations.

**Effort:** Medium
**Risk:** Medium - touches the root design contract, generated HTML template, subject theme tokens, responsive behavior, print behavior, and visual QA workflow.
**Decisions to sanity-check:** Execute this after the v3 educational upgrade; create root `DESIGN.md` first; use "classroom whiteboard workspace" as the direction; keep single-file vanilla HTML output; treat the design reference folder as inspiration only.

### Must NOT have (guardrails, anti-slop, scope boundaries)
- Do not implement design work before `DESIGN.md` exists and names the required primitives/states.
- Do not replace the builder with React, Tailwind, a web server, or a framework app.
- Do not clone Miro, IBM, Apple, Cursor, Airbnb, Dell, Nike, Voltagent, or any exact brand palette/typeface/logo.
- Do not use Dell 1996 retro styling, Nike campaign typography, Voltagent dark developer chrome, marketplace search bars, product tiles, IDE mockups, bokeh/orbs, generic AI gradients, or marketing hero composition as the default.
- Do not make the UI darker by default; classroom projection, print, and Korean public education tone require a light, inspectable surface.
- Do not add decorative motion, autoplay, timers, scoring, gamification, drag/drop, physics, or staged reveal without explicit user approval.
- Do not remove the existing three render modes (`교과용`, `발표용`, `퀴즈형`) or break existing v2-compatible specs.
